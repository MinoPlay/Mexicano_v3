Problem: the module is shallow relative to its size — the interface (60+ exported functions covering REST calls, push/pull queue, per-route pull logic, doodle changelog merge, ELO history cache, player-summary reads) is nearly as wide as the implementation, so no caller can predict what a change touches.

Solution: split into a thin API client (readFile/writeFile/authHeaders — the only place that talks HTTP), a sync queue (schedulePush/executePush/flushPush), and per-domain repositories (tournaments, doodle, players/elo) that each expose one narrow interface over the client.

  • leverage: one client interface, N repositories behind it — a REST-shape change touches one file
  • locality: a doodle bug can only live in the doodle repository, not scattered across a 2226-line file
  • interface shrinks: pages import a 5-function repository, not a 60-function grab-bag

2. Stop the backend module from knowing about routes

Strong ports & adapters

js/services/github.js: pullForRoute, refreshCurrentPage, _getRefreshSteps (lines 1710-1828)

Before

github.js
if (path === '/elo-charts') …
if (path === '/doodle') …
if (path === '/statistics') …

↑ backend module hardcodes every page's route string

After

home.js
calls tournamentsRepo.pull(), playersRepo.pull()
doodle.js
calls doodleRepo.pull(month)

↓ each page declares its own data needs against narrow repo interfaces

Problem: the seam is inverted — the low-level persistence module (github.js) knows the app's route strings ('/elo-charts', '/doodle'...) and decides per-page what to fetch, instead of pages declaring their own data needs. Adding a page means editing github.js's route table, not just the page.

Solution: move the "what does this page need" decision into each page module, calling the domain repositories from candidate 1 directly. Delete pullForRoute/_getRefreshSteps.

  • locality: a new page's data needs live in the new page, not in a shared route table
  • deletion test: deleting _getRefreshSteps today would concentrate breakage in github.js; after the split it disappears entirely
  • directly answers "changing one page breaks another" — this file is the shared point of failure

Problem: scoring/round/ELO decisions (createMexicanoMatches, setMatchScore, recalculateAllPlayerStats) and side-effecting persistence (saveTournamentState, triggerNewTournamentDayFile, runTournamentCompletion) live in the same module with no seam between them — testing a scoring rule means going through Store and, transitively, the push queue.

Solution: keep the engine functions pure (tournament in, tournament out) and move every Store/github.js call into a persistence-only layer that calls the engine, not the other way round.

  • locality: a scoring bug and a sync bug can no longer hide in the same function
  • tests hit the engine's interface directly, no Store/localStorage mock needed
⚠️ Overlaps candidate 1's push queue — sequence this after candidate 1 so persistence has one queue to call into, not two.

Top recommendation

Start with #1, collapse the GitHub-backend god module. It's the direct cause of "changing one page breaks another": every page imports the same 2226-line interface, so any deepening elsewhere is undermined until this seam exists. #2 falls out of #1 almost for free once repositories exist. #3 can wait.
